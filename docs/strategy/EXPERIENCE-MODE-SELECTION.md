# Charlie Architect — Choose the correct experience mode before designing

## Problem this solves
A reference-image experiment shows a risk: the user asks for a high-end cinematic product website, but an AI delivers an accurate hardware diagnostics interface. Engineering improves while the desired editorial experience becomes less compelling. These are **different product types**.

## Decide the experience category
| Type | Primary purpose | Design emphasis |
| --- | --- | --- |
| Editorial product showcase | Make the product desirable, memorable and explorable | Art direction, visual storytelling, tactile exploration, motion signature |
| Commercial site | Convert interest to real purchase or lead | Persuasion, trust, conversion, verified details |
| Interactive demonstration | Let people try a truthful simulation | Learnability, useful functionality, distinctive presentation |
| Diagnostic / productivity tool | Complete a repeatable job precisely | Speed, directness, tests, feedback, controls |
| Portfolio / experiment | Showcase ideas or creative work | Originality, narrative rhythm, precision |

**Default for image + "premium non-generic website with motion graphics":** editorial product showcase, possibly with a secondary working demo. Do NOT silently default to diagnostics, dashboards, test benches or dense utility panels if the user did not ask for that.

## Mandatory creative brief before coding
1. Mode and textual evidence that it fits the brief.
2. Emotional thesis: what should the product feel like?
3. Signature interaction derived from the product itself.
4. Hero composition: object scale, perspective, lighting, headline relationship.
5. Narrative chapters: distinct purpose and composition for each; no filler quota.
6. Visual contrast arc: how color/material/typography changes between chapters.
7. Motion arc: one or two memorable sequences + fast supporting interactions.
8. Primary real user action and honesty about what cannot be verified.
9. Concept veto: is this secretly a generic information site or diagnostics app?

## Editorial experience checks
- The hero and copy make the object compelling without lengthy functional explanation.
- The physical product or clearly labeled illustration is a visual protagonist.
- The experience progresses through meaningful chapters with contrasting pacing and layouts.
- Motion responds to product geometry and visitor action; not merely whole-object fade-in and uniform text entrance.
- A diagnostic tool may be included only if it supports the story and does not dominate the entire design.
- The final site has functional controls and accessibility without losing visual ambition.

## Creative director veto
Reject and redesign before implementation when: the brief calls for editorial delight but the largest UI block is a test panel; every section shares the same look; the product is a peripheral illustration; animation is reduced to generic reveal effects; the CTA takes the user to a task they never requested.

**If the user actually requests diagnostics, favor that mode and build it extremely well.** Do not impose a cinematic showcase over a utility brief.

## Final question
Did the implementation serve the *intended category* of experience, or did the AI replace creative judgment with a safe engineering feature list?
